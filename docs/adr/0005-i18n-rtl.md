# ADR 0005: Internationalisation with next-intl, locale-prefixed URLs, logical CSS

Status: accepted, 2026-10-15

## Decision
- `next-intl`, locales `en` and `ur`, URLs `/en/...` and `/ur/...` so both are indexable, with `hreflang` alternates.
- `dir="rtl"` for Urdu at the `<html>` level; Tailwind logical utilities only, enforced by lint.
- Noto Nastaliq Urdu loaded only on Urdu pages; Western digits for bond numbers and prices in both locales, isolated with `<bdi dir="ltr">`.
- Messages split per feature namespace file, one owner per file.
- Mobile uses the same message JSON (copied at build time from `apps/web/messages` by a script in `apps/mobile`) and `I18nManager.forceRTL`.

## Consequences
Translations need a native Urdu review before release (owner task). Locale-prefixed URLs double the sitemap size; acceptable.
